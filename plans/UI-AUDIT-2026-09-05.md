只读调研产物：不改代码，产出按界面分区的不一致清单 + 性价比排序的选题池。
后续任何改动先出 Plan Card（TASK-*.md + DoD），DoD 必带前后截图对比，设计决策

## 1. 系统性主题（跨界面，六条）

### T1 空态与加载态成体系缺失 —— 全场最大短板

App 里"等待"和"空"几乎都没有设计：

- share 网格加载 = 静态图标 + 一行字「正在获取共享列表…」，无 spinner
  （`ShareGridViewModel.swift:22` showLoading；图 21）。
- 空文件夹 = 整面裸底零提示（图 16）；零服务器无引导（图 01 只有占位文案
  「双击左侧服务器以连接」）。
- 目录切换无加载态，旧目录内容残留到新列表到达（BrowserViewController）。
- vault 图集：图片行永远只有 `photo` 占位符号（图 06；根因见 B2，代码如此
  而非慢）。
- 单页阅读器加载 = 黑屏 + 裸页码；条带阅读器"加载中"与"解码失败"共用同一
  占位，无法区分。
- 播放器加载/缓冲/失败仅在时间位置换一行字，无 spinner/中央状态
  （`PlayerViewModel.swift:297-304`，`PlayerWindowController.swift:543`）。
- 连接失败 = 占位区「双击重试」+ modal alert 双重提示同时出现（图 22）。

### T2 选中/强调色分裂：系统蓝 vs accentGold 两套语言

设计意图（`CoveStyle.swift:47` 注释）是 accentGold 用于 selected/active hints，
实际：

- 侧栏服务器行选中 = 系统蓝填充（图 25 中 `192.168.1.10` 蓝底）；本地仓库行
  选中同样是蓝（图 05）。
- 文件浏览器行选中 = 系统蓝（`BrowserViewController.swift:584-586` 用
  `selectedContentBackgroundColor`，crop-context-menu 可见蓝填充行）。
- 全 App 唯一金色选中态 = 播放列表当前行（金文字 + 金 speaker，
  crop-playlist-popover），以及本地仓库的硬盘图标（图 25 侧栏金图标）。
- 倍速/播放模式弹层的当前项用白色 checkmark（crop-speed-popover /
  crop-mode-popover），与播放列表的金色又是第三套。
- 播放器进度条/音量条 = 默认 NSSlider 系统蓝（crop-controls-capsule 两条蓝
  滑条在暖黑 + 金体系里格外冷）。

### T3 媒体 chrome 无令牌底座

阅读器/播放器的悬浮控件全是 ad-hoc 配方：

- 白色透明度六档并存：0.35 / 0.65 / 0.7 / 0.8 / 0.9 / 1.0（Reader + Player），
  无 overlay 文字层级令牌。
- 单页阅读器 = 裸白字页码 + 小 play 钮（crop-paged-chrome）；条带阅读器 =
  HUD pill（crop-strip-pill）——两种 chrome 语言并存。
- 条带 pill 的 hud 材质在浅色内容上几乎不可见：crop-strip-pill 里 play、
  1x、scrubber、页码看起来像直接浮在画面上，没有底板。
- FrostedCircleButton 填充配方（黑 0.35/0.55、白边 0.18）硬编码；pill 内
  间距 8/2/6/10/14、图标 10/12/13/16pt 四档全散点。

### T4 错误呈现原始化

- alert 的 informative 直接塞 `localizedDescription`：图 22 出现
  「Connection failed: 192.0.0.1: POSIXErrorCode(rawValue: 60)」这种裸错误串，
  用户看不懂，也不给下一步。
- 错误 alert 散在 4 处各自构造 NSAlert（无统一 ErrorPresenter，BACKLOG 已挂
  远期项）。
- 删除确认 alert 的「删除」按钮未标 `hasDestructiveAction`
  （`LibraryCoordinator.swift:201-206`、`:468-473`），不显示红色警示样式
  （图 24）。
- 播放器错误 alert 挂到主窗口而非播放器窗口
  （`PlayerCoordinator.swift:221` → `MainWindowController.swift:83`）。

### T5 排版刻度不守

CoveStyle 只有 4 档字体（14m/13/11/11sb，`CoveStyle.swift:20-26`），实际散点：

- 12pt 一族全无令牌：面包屑位置文本、等宽页码、倍速/时间码、Prefs 表单
  标签各自 ad-hoc。
- 9pt：条带速度档标签（`ContinuousReaderView.swift:146`），全 App 最小字，
  视网膜外基本不可读。
- 15pt semibold：阅读器缩放倍数闪现（`PagedReaderView.swift:170` /
  `ContinuousReaderView.swift:172`，两文件复制粘贴），不在刻度。
- 设置窗口四个分区标题用 13pt bold，偏离 `sectionHeaderFont`（11 semibold）
  令牌（`PreferencesWindowController.swift:194-197`，图 03 肉眼可见偏重）。

### T6 冷色入侵暖黑

- 倍速/播放列表/播放模式三个弹层用系统深灰（`.darkAqua` 系材质），与暖黑
  `#2C2929` 的 App 底色色温不一致（crop-speed-popover 等三张弹层图对比
  图 25 底色可见）；popover 箭头与内容区也存在色差。
- 系统蓝选中（T2）+ 蓝色 NSSlider（crop-controls-capsule）是暖黑界面里最
  突兀的冷色块。

## 5. 跨平台设计令牌沉淀建议（验收口径 2）

现状令牌只有 3 圆角 + 4 字体 + 3 色 + 1 边框色（`CoveStyle.swift:7-47`），
上面的散点问题大半源于"想用没得用"。建议每个 UI 任务交付时同步维护一份
**平台无关**令牌文档（建议落 `design/DESIGN-TOKENS.md`，与 logo 源文件同目录），
结构按"决策"而非"代码"组织：

- **色**：角色语义命名（surface-base / surface-raised / accent / text-primary /
  text-secondary / text-on-media-{1,2,3} / danger / selection），每条记色值 +
  用途 + 首次引入的任务单号；Mac 端实现（NSColor/暖黑 hex）只是该角色的一个
  平台绑定，iPad 端重写时照角色映射 UIKit。
- **字**：刻度表（目前事实刻度 9/11/12/13/14/15pt 六档，建议收敛为
  caption/secondary/body/title/overlay 五档 + 等宽数字变体），不记 NSFont。
- **间距/尺寸**：4pt 网格刻度（4/8/12/16/20/24…），行高、badge、inset 按档
  位登记；不记 SnapKit 代码。
- **圆角**：现状 6/12/14 + 散点 8，建议收敛为 small/medium/large 三档语义。
- **动效**：时长/曲线档位（如 fast 0.15s），不记 CA 代码。
- **组件配方**：pill 底板、卡片描边、选中态等"跨平台想要同一个效果"的配方，
  用文字+色值描述，AppKit 特有技巧（HUD 材质、vibrancy）标注"平台实现细节，
  够用即可"。

Mac 端 `CoveStyle` 保持代码令牌的单一事实来源，`DESIGN-TOKENS.md` 是其平台
无关投影；两者冲突时以文档为准修代码。
